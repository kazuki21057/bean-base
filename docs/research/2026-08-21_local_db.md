# Flutter向けローカルDBパッケージ比較調査レポート(T5-B10)

- 調査日: 2026-08-21
- 調査目的: トラックB「将来的なローカルDB導入検討」向けに、次タスクT5-B11(ローカルDBスキーマ設計、上位モデル実施予定)の判断材料として、Flutter向けローカルDBパッケージ`drift`/`isar`/`sqflite`を比較する。最重要判断軸は「型安全なマイグレーション基盤の有無」。
- 調査範囲: pub.dev公式パッケージページ、公式ドキュメント(drift公式サイト)、GitHub公式リポジトリ(isar)を情報源とした。実装コード・スキーマ設計そのものは範囲外(T5-B11の作業)。

## 確認済みの事実

### drift

- [C1] pub.dev上の`drift`は「Drift works on Android, iOS, macOS, Windows, Linux and the web」と説明されており、Webを含む全プラットフォームに公式対応している(出典: pub.dev/packages/drift、取得日2026-08-21)。
- [C2] 「Drift has builtin support for transactions, schema migrations, complex filters and expressions, batched updates and joins」と明記され、スキーマ・マイグレーションが組み込み機能である(出典: pub.dev/packages/drift、取得日2026-08-21)。
- [C3] 「Drift generates type-safe code based on your tables and queries」「Drift lets you write queries in both SQL and Dart, providing fluent apis for both languages」とあり、SQL・Dart両方で型安全なクエリビルダを提供する(出典: pub.dev/packages/drift、取得日2026-08-21)。
- [C4] drift公式ドキュメントのマイグレーション章では、`make-migrations`コマンドにより「A step-by-step migration file will be generated next to your database class」「Drift will also generate a test file for your migrations」と説明されており、スキーマバージョン(`schemaVersion`)ごとの段階的マイグレーションファイルと、それを検証する自動生成テスト(データ整合性テストを含む)がツールチェーンとして提供されている(出典: https://drift.simonbinder.eu/migrations/ 、取得日2026-08-21)。
- [C5] pub.dev上で`drift`は最終更新24日前、Pub Points 70、Likes 2,450(2.45k)と表示されている(出典: pub.dev/packages/drift、取得日2026-08-21)。

### isar

- [C6] pub.dev上で`isar`の最新stableバージョンは3.1.0+1、最新prerelease(v4系)は4.0.0-dev.14で、いずれも公開から約3年が経過している(出典: pub.dev/packages/isar/versions、取得日2026-08-21)。
- [C7] `isar`のGitHub公式READMEには「⚠️ ISAR V4 IS NOT READY FOR PRODUCTION USE ⚠️ If you want to use Isar in production, please use the stable version 3.」と明記されており、v4は本番未対応、v3(3年前公開)が推奨版のままである(出典: https://github.com/isar/isar 、取得日2026-08-21)。
- [C8] pub.dev上の`isar`はPub Points 130、Likes約2.4kで、プラットフォーム対応欄にWebが列挙されている(出典: pub.dev/packages/isar、取得日2026-08-21)。ただしマイグレーション機能に関する説明はpub.devページ上に見当たらなかった。
- [C9] コミュニティフォーク`isar_community`はpub.dev説明文で「このリポジトリは元のプロジェクトのフォークで、バージョン3のバグ修正と小規模なアップデートに主眼を置いている」とされ、最終更新は5ヶ月前、Pub Points 140、Likes 159。プラットフォーム対応はiOS/Android/Desktopの列挙にとどまり、Web対応・マイグレーション機能の明示的な記述は確認できなかった(出典: pub.dev/packages/isar_community、取得日2026-08-21)。

### sqflite

- [C10] pub.dev上の`sqflite`は最終更新2ヶ月前、Pub Points 160、Likes 5,560と、3パッケージ中もっとも活発な更新頻度と支持を示している(出典: pub.dev/packages/sqflite、取得日2026-08-21)。
- [C11] Web対応は別パッケージ経由の実験的対応にとどまり、「Experimental Web support using sqflite_common_ffi_web」と明記されている(出典: pub.dev/packages/sqflite、取得日2026-08-21)。
- [C12] マイグレーション機能は「There is a basic migration mechanism to handle schema changes during opening」とあるのみで、`onUpgrade`コールバック内に生SQLを手書きする素朴な仕組みであり、型安全性や自動検証ツールは公式パッケージ自体には含まれない(出典: pub.dev/packages/sqflite、取得日2026-08-21)。マイグレーションを補強する`sqflite_migration`等のサードパーティパッケージが別途存在する(出典: WebSearch結果、取得日2026-08-21、URLは出典一覧参照)。

## 比較表

| パッケージ | マイグレーション基盤 | Web対応 | 型安全性(クエリビルダ) | 保守状況 | 学習コスト |
|---|---|---|---|---|---|
| **drift** | 組み込み。`schemaVersion`+段階的マイグレーションファイルを`make-migrations`で自動生成、専用テストで検証可能(型安全) [C2][C4] | 公式対応(Android/iOS/macOS/Windows/Linux/Web) [C1] | 高。テーブル定義からDartコードを生成、SQL/Dart両対応の型安全クエリ [C3] | 良好。最終更新24日前、Likes 2,450、Pub Points 70 [C5] | 中〜高。コード生成(build_runner)前提、独自DSL/アノテーションの習得が必要 |
| **isar** | 公式パッケージにマイグレーション機能の明記なし [C8]。v4は本番未対応の警告あり [C7] | pub.dev上はWeb列挙 [C8]だが本体開発が3年前で停滞、コミュニティフォークもWeb明記なし [C9] | 高(NoSQLコレクション定義からコード生成)だが本体は事実上更新停止 | 停滞。stable/prerelease双方とも公開から約3年更新なし [C6][C7]。フォーク`isar_community`は5ヶ月前更新だがバグ修正中心 [C9] | 中。独自のNoSQLモデルを新規に学ぶ必要 |
| **sqflite** | 公式は素朴な`onUpgrade`手書きのみ、型安全性なし [C12]。サードパーティ補完パッケージ有り | 実験的(別パッケージ経由) [C11] | 低。生SQLを文字列で記述、コンパイル時チェックなし | 最良。最終更新2ヶ月前、Likes 5,560、Pub Points 160(3者中最高) [C10] | 低。SQLiteの素のAPIに近く既存SQL知識で着手可能 |

## 推測・未確認

- `sqflite_migration`等のサードパーティ移行支援パッケージの型安全性・保守状況は検索結果の要約のみに基づき、pub.devページを個別に精査していない(範囲外)。「マイグレーション基盤の有無」の主軸判断には`sqflite`本体の仕様を採用した。
- isarのWeb対応「pub.dev上の列挙」と実際の`sqlite3.wasm`ベースの動作確認は未実施(本体開発停滞のため実用性は低いと推測されるが未検証)。
- drift公式ページに「sqlite3.wasm」という語そのものは今回のFetch結果内に明示的に見当たらなかった(Web対応自体は明記されている)。Web版での具体的な永続化方式(OPFS/IndexedDB経由か等)は今回のスコープでは深掘りしていない。

## 変動しうる情報への注記

- Likes/Pub Points/最終更新日・バージョン番号はpub.devの動的な値であり、T5-B11着手時や実際の導入判断時に再確認が必要。
- isarの開発状況(v4正式リリースの有無、isar_communityの活発度)は変化しうるため、実装フェーズ直前に再確認すること。

## 最終推奨

**drift**を推奨する。理由:
1. 最重要軸である「型安全なマイグレーション基盤」を唯一、公式ツールチェーンとして提供している(`make-migrations`によるスキーマバージョンごとの段階的マイグレーション生成+自動検証テスト、[C4])。sqfliteは生SQL手書き、isarは本体に明記された機能がなく開発自体も停滞している。
2. BeanBase 2.0はWeb(Chrome)が主要検証ターゲットであり、drift公式にWebサポートが明記されている([C1])。isarはWeb対応が不透明かつ本体開発停滞([C6][C7][C9])、sqfliteのWeb対応は実験的([C11])。
3. 保守状況は3者中2番目(sqfliteが最良)だが、isarの3年間の停滞([C6][C7])と比べると実運用リスクは低い。
4. 学習コストはbuild_runner前提でやや高いが、BeanBase 2.0は既に`json_serializable`のコード生成パイプラインを採用済み(`CLAUDE.md`記載)であり、追加の学習・運用コストは相対的に小さいと考えられる(この点はリポジトリ内既存構成からの推測であり、drift自体の調査結果ではない)。

## 積み残し・判断が必要な点

- 実際のスキーマ設計(テーブル定義、Sheetsとの同期戦略)はT5-B11の範囲であり本調査では扱っていない。
- `sqflite_migration`系サードパーティパッケージの詳細評価、`isar_plus`フォークの検証は範囲外として未調査。
- Web版での永続化層(IndexedDB/OPFS)の技術的な相性については、drift公式ドキュメントの当該節を別途読む必要があるかもしれない(今回はトップページ相当の情報のみ確認)。
