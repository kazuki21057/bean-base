# 注湯ステップ・ハイライトずれ 修正設計書(T3-80c → 実装はT3-80d)

作成: 2026-08-05(上位モデル=Opus 5)。実装: 下位モデル(Sonnet 5)。
入力: `docs/pouring_highlight_verification_plan.md` に基づくT3-80bの検証報告(2026-08-05)。

## 1. 根本原因(確定)

検証で取得した本番`pouring_steps`実データにより、**データの意味論が確定した**。

`method001`(4:6メソッド)の各行の「表示される経過時間」は **0:00 / 0:45 / 1:30 / 2:10 / 2:45 / 3:30**。これは粕谷式4:6メソッドの**実際の注湯タイミングそのもの**である(0:00蒸らし、0:45・1:30・2:10・2:45に注湯、3:30にドリッパーを外す)。`654c2399`(井崎式)も同様に 0:00 / 1:00 / 2:00 / 2:00 / 3:00 で、実際の注湯時刻と一致する。

したがって:

- **`加算時間（秒）`は「その行の操作を行うまでの待ち時間」**であり、「その行の操作の所要時間」ではない。
- **行に表示される累計時間(`stepEndTime`)は「その行の操作を行う時刻」**であり、表示仕様は**正しい**。`加算湯量`の累計を「その時点までに注ぎ終えているべき総湯量」として表示しているのとも整合する。
- 先頭が`加算時間=0`の行になっているのは「0:00に最初の操作(蒸らし・氷投入等)を行う」ことの表現であり、データも正しい。

**バグは点灯窓の定義だけ**。現行の`activeStepIndex()`(`lib/utils/pouring_step_highlight.dart:17`)は行 *i* を **[前の操作時刻, 自分の操作時刻)** の間だけ光らせている。つまり **自分の操作時刻が来た瞬間に次の行へ移ってしまう** = 常に1行先を光らせている。これがユーザーの言う「ずれている」の正体。

T3-79(2026-08-04)は「0秒ステップに点灯を譲るかどうか」という**症状の一部**を直しただけで、点灯窓そのものは手つかずだった。だから「またずれている」。

## 2. 修正(1) 点灯窓の定義を変える — 本丸

### 新しい仕様

各行 *i* の**操作時刻** `actionTime(i)` = 先頭から行 *i* までの`加算時間`の累計(= 画面に表示されている時刻)と定義する。

> **行 *i* は、`actionTime(i)` が到来した時点から、次の操作時刻が到来するまでの間、点灯し続ける。**

- **同じ操作時刻を持つ行が複数ある場合は、それら全部を同時に点灯させる**(H6)。井崎式の2:00は「2投目より強く注ぐ」と「3回スピン」を同時に行うのが実態であり、どちらか一方だけを光らせるのは誤り。
- 経過時間が最初の操作時刻に達していない場合は、**先頭行**を点灯させる(直後に来る操作の予告。実データは全メソッドが先頭`加算時間=0`なので実際にはほぼ発生しないが、防御的に定義する)。
- **最後の操作時刻を過ぎても、最終行を点灯させ続ける**(H4)。最終行は「ドリッパーを外す」「抽出完了」等、まさにその時に見たい情報であり、消灯は有害。
- **0秒ステップの「点灯を譲る」ロジックは全廃**する。操作時刻ベースにすると0秒ステップも自然に自分の窓を持つため、T3-79で入れた`description`の空判定は**不要になるので削除**する。

### 実装

`lib/utils/pouring_step_highlight.dart` を**全面的に書き換える**。関数名・戻り値の型を変更する(単一indexでは同時刻の複数行を表現できないため)。

```dart
import '../models/pouring_step.dart';

/// タイマー連動で点灯させるステップ(0始まりindex)の集合を返す。
///
/// 各ステップの「操作時刻」は、先頭からそのステップまでの「加算時間(秒)」の
/// 累計であり、画面の「経過時間」列に表示されている値と一致する。
/// `加算時間`は**そのステップの操作を行うまでの待ち時間**であって、操作自体の
/// 所要時間ではない(本番データで確認済み。例: 4:6メソッドは 0:00 蒸らし →
/// 0:45 / 1:30 / 2:10 / 2:45 に注湯 → 3:30 ドリッパーを外す)。
///
/// そのため、あるステップは**自分の操作時刻が到来してから、次の操作時刻が
/// 到来するまで**点灯し続ける。操作時刻が同じステップが複数ある場合
/// (0秒ステップとその直後など)は、それらを**同時に**点灯させる。
/// 最後の操作時刻を過ぎた後は最終ステップを点灯させ続ける。
///
/// 過去バージョンは点灯区間を[前の操作時刻, 自分の操作時刻)としていたため、
/// 常に1ステップ先を点灯させており、実際の注湯タイミングとずれていた(T3-80)。
Set<int> activeStepIndexes(List<PouringStep> steps, double elapsedSec) {
  if (steps.isEmpty) return const <int>{};

  final actionTimes = <int>[];
  var cumulative = 0;
  for (final step in steps) {
    cumulative += step.duration;
    actionTimes.add(cumulative);
  }

  // 最初の操作時刻より前は、直後に来る先頭ステップを予告点灯する。
  if (elapsedSec < actionTimes.first) return <int>{0};

  // 直近に到来した操作時刻を求める(最後の操作時刻を過ぎた後はそれを保持)。
  var current = actionTimes.first;
  for (final t in actionTimes) {
    if (t <= elapsedSec) {
      current = t;
    } else {
      break;
    }
  }

  final result = <int>{};
  for (var i = 0; i < actionTimes.length; i++) {
    if (actionTimes[i] == current) result.add(i);
  }
  return result;
}
```

**注意**: `actionTimes`は`加算時間`が非負である前提。負値は本番データに存在しない(エディタ側も`newDuration >= 0`でガード済み)。

### 呼び出し側

`lib/screens/brew_recipe_screen.dart:165-168` の`_activeStepIndex`を`_activeStepIndexes`(`Set<int>`)に変える。§3の変更も同時に入れること。

`lib/widgets/method_steps_editor.dart`:

- パラメータ `final int? activeStepIndex;` → **`final Set<int> activeStepIndexes;`**(コンストラクタのデフォルトは `const <int>{}`。従来どおり未指定なら点灯なし)
- `:85` の判定 → `widget.activeStepIndexes.contains(i) ? Colors.amber.shade100 : null`
- 他の呼び出し元(`method_detail_screen.dart` / `method_create_screen.dart`)は引数を渡していないのでデフォルト値のまま変更不要。**渡している箇所が他に無いかは`Grep`で必ず確認する**こと。

## 3. 修正(2) 一時停止で消灯しない(H5)

`lib/screens/brew_recipe_screen.dart` の現行実装は`_stopwatch.isRunning`が偽なら常に`null`を返すため、**一時停止した瞬間にどの行が現在の手順かわからなくなる**。湯量を量り直す・豆を追加する等で止めた直後に情報が消えるのは有害。

```dart
  Set<int> get _activeStepIndexes {
    // リセット直後(未計測)のみ消灯。一時停止中は直前の位置を保持する。
    if (_stopwatch.elapsedMilliseconds == 0) return const <int>{};
    return activeStepIndexes(_workingSteps, _stopwatch.elapsedMilliseconds / 1000);
  }
```

`_resetTimer()`は`_stopwatch.reset()`で経過0に戻すため、リセットで消灯する挙動は維持される。

## 4. 修正(3) メソッド切替後に「経過時間」「説明」列が古いまま残る

検証で1回観測された表示不整合(湯量列だけ新メソッドの値に切り替わり、経過時間・説明列は旧メソッドのまま)。**原因は特定済み**:

`lib/widgets/method_steps_editor.dart`の3つの`TextFormField`のうち、湯量列だけが`key: ValueKey('water_${i}_${widget.baseBeanWeight}_...')`を持つ(T3-58で追加)。時刻列・説明列は**キーを持たないためElementが再利用され、`initialValue`が初回生成時にしか反映されない**。メソッドを切り替えて`_steps`が入れ替わっても、同じ行位置のフィールドは古いテキストを保持し続ける。湯量列だけキーが変わって更新されるので「湯量だけ切り替わる」という観測と一致する(=再現性のある決定的な不具合)。

**修正**: 時刻列・説明列の`TextFormField`に**ステップIDに基づくキー**を付ける。

```dart
key: ValueKey('time_${s.id}'),   // 時刻列
key: ValueKey('desc_${s.id}'),   // 説明列
```

`s.id`はステップごとに一意で、メソッドを切り替えれば必ず変わる。**入力中に値が変わってもキーは変わらない**ため、フォーカス・カーソル位置は保たれる(`_updateStep`は同じ`id`で新インスタンスを作るだけ)。

> **既知の制限(今回は対応しない)**: 行 *i* の時刻を編集しても、後続行の表示(累計)はキーが変わらないため即時には更新されない。これは本修正以前からの挙動であり、ユーザーからの指摘も無いため対象外とする。設計判断が必要になったら止めて報告すること。

## 5. 修正(4) メソッド切替時にタイマーをリセットする

現行の`_onMethodSelected`はストップウォッチに触れないため、**前のメソッドの計測時間が引き継がれる**(検証中に「切替後、再生ボタンを押してもタイマーが動かない/00:00のまま」という混乱が起きた原因もここにある可能性が高い)。メソッドを切り替えたら計測はやり直しになるのが自然。

メソッド選択時のstate更新の中で、以下を行う:

```dart
    _timer?.cancel();
    _timer = null;
    _stopwatch.stop();
    _stopwatch.reset();
```

`dispose`との二重cancelは問題ない。**この変更で「切替後にタイマーが動かない」現象が解消するかを実機で確認**し、解消しなければ**そこで止めて報告する**(追加調査は次フェーズ)。
