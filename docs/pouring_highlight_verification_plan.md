## 2. 現状の実装(再調査不要。この前提のまま検証してよい)

| 場所 | 挙動 |
|---|---|
| `lib/utils/pouring_step_highlight.dart:17` `activeStepIndex(steps, elapsedSec)` | 各ステップの点灯区間を **[累計開始秒, 累計開始秒+duration)** とし、`elapsedSec`が入る最初の非0秒ステップのindexを返す。`duration==0`のステップは自身の区間を持たず、**直後の非0秒ステップの`description`が空文字のときだけ**その区間を0秒ステップ側へ譲る。合計時間を超えた場合と空リストは`null` |
| `lib/screens/brew_recipe_screen.dart:165-168` `_activeStepIndex` | **Stopwatch動作中のみ**値を返す(停止・一時停止中は`null`=消灯)。経過秒は`elapsedMilliseconds / 1000`の実数 |
| `lib/screens/brew_recipe_screen.dart:96-97` | ステップは`stepOrder`昇順にソートして`_workingSteps`へ格納(並び順の乱れは起きない想定) |
| `lib/widgets/method_steps_editor.dart:67-101` | 「経過時間」列に表示するのは**そのステップの開始時刻ではなく`stepEndTime`(= そのステップが終わる時点の累計秒)** |
| `lib/widgets/method_steps_editor.dart:85` | 行の背景色は `i == widget.activeStepIndex` のとき amber |
| `lib/screens/brew_recipe_screen.dart:528` `_formatTimerUI` | タイマー表示は mm:ss(秒未満切り捨て) |

**この2点の組み合わせが重要**: 行に表示されている時刻は**そのステップが終わる時刻**であり、ハイライトはその時刻の**手前の区間**で点灯する。つまり「0:45」と表示された行は 0:00〜0:44 の間ずっと点灯している。この仕様が正しいかどうかは判断せず、§5で**事実として観測・記録する**。

データ列の対応(`lib/services/sheets_service.dart:231-243`、全角括弧に注意):

`ID`→id / `メソッドID（親）`→methodId / `並び順`→stepOrder / `加算時間（秒）`→duration / `加算湯量（ml）`→waterAmount / `湯量基準(豆量15g)`→waterReference / `湯量係数`→waterRatio / `注意事項`→description

## 3. 検証すべき仮説(H1〜H7)

各仮説について §7 の報告で「**観測された / 観測されなかった / 検証不能**」を必ず判定すること。

| ID | 仮説 | 判別方法 |
|---|---|---|
| H1 | **表示時刻と点灯区間の意味が1行ずれて見える**。行の時刻=終了時刻なのに点灯はその手前の区間のため、「表示時刻=その操作を行う時刻」と読むユーザーには常に1行先行して見える | §5-B。タイマー表示 t のとき、点灯行の表示時刻が t より**大きい**(=まだ来ていない時刻の行が光っている)かを記録 |
| H2 | **0秒ステップの譲渡条件**(直後ステップの説明文が空のときだけ譲る)が本番の一部メソッドで実際の操作順と食い違う | §5-A で0秒ステップを含む全メソッドを洗い出し、譲渡が起きる行/起きない行を表にする |
| H3 | **データ側の問題**。`加算時間（秒）`が「加算」ではなく累計で入力されている行、0が並ぶ行、合計湯量と`methods_master`の基準湯量の不一致(既知: 654c2399・ed6f2106、`NEXT_SESSION.md`§継続中の注意事項9) | §5-A。各メソッドの加算時間の並びが単調に増える累計値に見えないか確認 |
| H4 | **合計時間を超えると`null`**になり、最後の操作(落ち切り待ち等)の最中に消灯する | §5-B-3 の合計時間超過後の撮影 |
| H5 | **一時停止・リセットで消灯**する(停止中は必ず`null`) | §5-B-4 |
| H6 | **同じ表示時刻の行が2行並ぶ**(0秒ステップとその直後)ため、どちらが光っても片方は「ずれている」ように見える | §5-A の表で表示時刻が重複する行を抽出 |
| H7 | **秒未満の境界**。タイマー表示は切り捨て、判定は実数秒のため、境界前後の1秒未満だけ見かけ上ずれる | §5-B。1秒未満の一過性のずれは**不具合として扱わず**、その旨を記録するだけでよい |

## 5. 検証手順

### A. 机上検証(データ × ロジック)

**A-1.** 取得した全メソッドについて、次の表を作る(1メソッド1表、**0秒ステップを含むメソッドは必須**、含まないメソッドは代表1件でよい)。

| 並び順 | 加算時間(秒) | 表示される経過時間(累計・mm:ss) | 説明文(注意事項) | 実装上の点灯区間(秒) |
|---|---|---|---|---|

点灯区間は§2の`activeStepIndex`の規則を**手計算で**適用する(規則は単純なので実装を動かす必要はない)。手計算の妥当性は`test/pouring_step_highlight_test.dart`の既存8ケース(4:6メソッド型・井崎式型)と突き合わせて自己検証すること。

**A-2.** 上表から次を抽出する:

- 表示時刻が**重複する行**の組(H6)
- **どの区間でも点灯しない行**(0秒ステップが譲れなかったケース、最終行以降など)
- 加算時間の並びが**累計値に見えるメソッド**(H3)

### B. 実機ブラウザ検証

**B-1.** `flutter build web` → `build/web`を**未使用ポート**でローカル配信 → `claude-in-chrome`で開く(Service Workerキャッシュ回避のため毎回ポートを変える。手順は`docs/deploy.md`・`rules/verification.md`)。抽出画面(`BrewRecipeScreen`)の画面IDと導線は`lib/routing/app_screen.dart`で確認してから開くこと。

**B-2.** 検証対象メソッドは**最低2つ**:

- `method001`(4:6メソッド) — 0秒ステップの直後が空説明のパターン
- `654c2399`(井崎式) — 0秒ステップの直後にも独自説明があるパターン
- A-2で「どの区間でも点灯しない行」を持つメソッドが他にあれば**1つ追加**

**B-3.** メソッド選択後、豆量は初期値のままタイマーを開始し、**止めずに**以下のタイミングでスクリーンショットを撮る(タイマー表示が同じ画面に写るように全体を撮ること):

1. t ≒ 5秒(最初の区間の内側)
2. 最初の区間境界の**直前**(境界−3秒程度)
3. 最初の区間境界の**直後**(境界+3秒程度)
4. 中盤の区間境界の直後
5. 合計時間を**超えた後**(合計+5秒程度、H4)

**B-4.** 続けてタイマーを一時停止し、点灯が消えるかを1枚撮る(H5)。その後リセット。

**B-5.** 各スクリーンショットについて次の3点を記録する:

- タイマー表示(mm:ss)
- **amberで光っている行**の「表示されている経過時間」と「説明文」
- その時点で実際に行うべき操作(説明文から読み取れる範囲。読み取れなければ「不明」)

**B-6.** `read_console_messages`(pattern指定)でエラー0件を確認。

**制約**: スクリーンショットは**合計12枚以内**。ページテキストの取得は`get_page_text`/`find`を優先し、色の確認が必要な場面だけスクリーンショットを使う(`CLAUDE.md`§トークン運用規約)。

### C. 切り分け(Aと Bで食い違いが出た場合のみ実施)

- 豆量を15g→20gに変更しても「経過時間」列が変わらないことを確認(変われば別の不具合)。
- 経過時間セルを手編集した直後にハイライト行がずれないか確認(エディタ内部の`_steps`と親の`_workingSteps`のindex対応)。
